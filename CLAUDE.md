# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Cos'è

Applicazione desktop Windows (Python 3.12, customtkinter) che estrae gli articoli da un listino prezzi PDF e li esporta nel foglio Excel `Listino`, con le colonne che il listino ha (profilo JBL: **Modello | Codice | EAN | Descrizione | Prezzo**). Il motore è universale: ricava colonne e articoli dalla geometria del documento. Un fornitore nuovo si configura dal wizard «Configura nuovo fornitore» e finisce nelle regole personali. Il profilo distribuito è quello del listino JBL di Exhibo (gennaio 2026: 121 pagine, 673 articoli). Il progetto è in italiano: commenti, messaggi di commit e interfaccia sono in italiano.

## Ambiente (vale su questa macchina)

- C: è stretto: prefissare i comandi con `$env:TMP='D:\tmp'; $env:TEMP='D:\tmp'` (PowerShell).
- Le dipendenze sono gestite con `uv`. I listini reali `samples/Listino_JBL_Gen_2026.pdf`, `samples/Etabeta_Larentis.pdf`, `samples/Midiware_Listino.pdf` (ottobre 2018, quattro prezzi per riga) e `samples/Midiware_2_Listino.pdf` (giugno 2017, tre prezzi) e `samples/Compumania_Listino.pdf` (gennaio 2014, esportato da Excel, 61 pagine, 4.698 articoli) sono esclusi da git (materiale commerciale). I test che li usano si saltano se il file manca.
- **`%LOCALAPPDATA%\PDFListinoExtractor\supplier_rules.json` contiene i fornitori veri dell'utente**, creati col wizard (JBL, GTD, JVL). Non leggerlo per prova, non sovrascriverlo, non cancellarlo. I test usano `monkeypatch.setenv("LOCALAPPDATA", tmp_path)`, e `tools\collaudo_installer.ps1` lancia il programma con una `%LOCALAPPDATA%` di prova in `D:\tmp`. Ogni nuovo collaudo deve fare lo stesso.
- Inno Setup 6 è installato per utente, in `%LOCALAPPDATA%\Programs\Inno Setup 6`. Tesseract non è installato, quindi il test OCR viene saltato.
- Windows PowerShell 5.1: `git push` e altri comandi nativi che scrivono su stderr fanno uscire con codice 255 anche quando riescono. Verificare con `git ls-remote` o `git status -sb`, non dal codice d'uscita. Con `gh ... --jq` le virgolette si rompono: meglio `--json` piu' `ConvertFrom-Json`.

## Comandi

```powershell
uv run python main.py                                   # avvio dal sorgente
uv run pytest -q                                        # suite completa (283 test, 1 saltato senza Tesseract)
uv run pytest tests/test_pdf_extraction.py -v           # un file
uv run pytest tests/test_gui.py::test_ordinamento_per_prezzo_con_mancanti_in_fondo -v   # un test
uv run ruff check .                                     # lint (config in pyproject.toml)
uv run python tools/misura.py <pdf> [--profilo]         # tempi di estrazione senza interfaccia
uv run python tools/analizza_pdf.py <pdf> [1,27]        # testo con coordinate, per i casi che il wizard non copre
uv run python tools/prova_gui.py <pdf> <out.xlsx>       # collaudo della finestra vera (report .collaudo.json)
uv run python tools/prova_wizard.py <pdf> <out.png> [pagina]   # collaudo visivo del wizard, non salva nulla
uv run python tools/misura_copertura.py <pdf> [pagina]  # prezzi del PDF attribuiti a un articolo, con la proposta del wizard
uv run python tools/misura_copertura.py samples\Etabeta_Larentis.pdf 22   # la misura di riferimento sul catalogo
uv run python tools/misura_copertura.py samples\Midiware_Listino.pdf 3    # piu' prezzi per riga: 99,9%
uv run python tools/misura_copertura.py samples\Compumania_Listino.pdf 1  # colonne senza etichetta: 100%
```

`misura_copertura` è la misura di qualità indipendente dal motore. Conta, pagina per pagina, le scritte con la forma di un prezzo e le confronta con gli articoli che ne hanno uno. Una pagina «in eccesso» vuol dire un prezzo inventato, una «con perdite» articoli persi. Sul catalogo Etabeta, con la proposta del wizard su pagina 22: 97,8%, 0 pagine in eccesso. La pagina va indicata. Senza, vale la pagina 1, che è l'indice: la proposta è sbagliata (6.465 «articoli», colonne «Colonna 1/2/3») e la percentuale non significa nulla. Contano anche i prezzi delle colonne «Altro prezzo»: sui listini Midiware 99,9% (pagina 3; mancano due righe senza codice con prezzi 0,00) e 100% (pagina 1). Prima di cambiare il motore conviene salvare in un JSON fuori dal repository l'estrazione del JBL (profilo distribuito e proposta del wizard) e quella dell'Etabeta (proposta su pagina 22), e confrontarle campo per campo dopo la modifica. È così che sono stati trovati i difetti di raggruppamento, e che si vede se una regola cambia i prezzi oltre alle descrizioni.

Distribuzione:

```bat
scripts\build_exe.bat          rem sync + test + PyInstaller -> dist\PDFListinoExtractor\ (onedir)
scripts\build_installer.bat    rem Inno Setup -> dist\PDFListinoExtractor_Setup.exe
uv run python scripts\imposta_versione.py 1.3.0    rem unica via per cambiare versione (version.py + pyproject.toml)
powershell -ExecutionPolicy Bypass -File tools\collaudo_installer.ps1 <setup_vecchio> <setup_nuovo> <pdf>
```

`PDFListinoExtractor.exe --collaudo <pdf> <out.xlsx>` collauda l'eseguibile impacchettato: apre la finestra, estrae, esporta e scrive un report JSON. `--collaudo-wizard <pdf> <regole.json> [pagina]` fa lo stesso col wizard, dall'analisi al salvataggio, scrivendo nel file indicato e non nelle regole dell'utente. Su un catalogo va indicata una pagina con una tabella: la prima è spesso l'indice, e lì la proposta non ha senso. Serve anche a verificare che `jsonschema` e lo schema siano inclusi dal `.spec`. `tools\collaudo_installer.ps1` installa per l'utente corrente, aggiorna, disinstalla e verifica 21 punti; l'installazione in Program Files (UAC) non si può automatizzare. Il setup della versione precedente va copiato fuori da `dist` prima di compilare il nuovo, perché viene sovrascritto.

Rilascio, come per le versioni 1.0.0–1.3.0: tag leggero `vX.Y.Z` sul commit «chore: versione X.Y.Z» e release GitHub con `PDFListinoExtractor_Setup.exe` allegato. Le note sono in italiano e scritte per l'utente: Novità, Aggiornamento, Verifiche, SHA-256 del setup.

## Architettura

Flusso: `extractors/pdf_reader` (apertura e verifica, sola lettura) → `extractors/text_extractor` oppure `ocr_extractor` (produce `Span` con le coordinate) → `extractors/table_extractor` (geometria: statistiche del documento, testate ripetute, intestazione, colonne fisiche) → `processors/raggruppamento` (righe → articoli, funzioni pure) → `processors/article_parser` (campi) → `processors/data_validator` → `exporters/excel_exporter`. A orchestrare è `processors/estrazione.estrai_listino`, in **due passate**: le soglie sono statistiche dell'intero documento, quindi prima si leggono tutte le pagine e poi le si interpreta. L'interfaccia in `gui/` non contiene logica di estrazione. Il wizard ha la sua logica in `processors/wizard.py` (`ModelloWizard`, senza Tk) e la pre-analisi in `processors/analisi_layout.py`. Progetto e motivazioni: `docs/progetto-estrazione-universale.md`.

**Nessuna coordinata fissa.** Il profilo (schema 2, `config/supplier_rules.schema.json`, completato da `processors/profilo.normalizza`) dice solo quale colonna contiene quale campo. Ogni distanza è un multiplo del corpo o dell'interlinea mediana del documento. Non aggiungere soglie in punti assoluti. **I casi di non regressione sono due e vanno tenuti entrambi.**
- **Listino JBL**: stessi 673 articoli del motore a coordinate fisse, campo per campo, sia col profilo distribuito sia con la sola proposta del wizard (`tests/test_universale.py`).
- **Catalogo Etabeta** (`tests/test_catalogo.py`, PDF vero + `tests/sintetico_catalogo.py`): almeno il 97% dei prezzi attribuiti e nessuna pagina in eccesso.

Una regola nuova che aggiusta uno dei due rompe spesso l'altro: è successo più volte. Il motore è anche provato su un layout opposto (`tests/sintetico_generico.py`, con e senza intestazione).

Scelte non ovvie, ognuna motivata da una misura o da un difetto reale:

- **L'articolo si individua dall'ancora**, cioè il campo scelto nel profilo o dedotto per densità: codice, poi EAN, poi modello, poi prezzo, il primo che copre almeno il 60% del campo più denso. Il prezzo è l'ultima scelta perché è il campo che può mancare: ancorando sul prezzo, un articolo senza prezzo si fonde con quello sopra (c'è un test che lo dimostra). Il prezzo è quello che cade nell'estensione verticale dell'articolo: se ce ne sono due **non se ne sceglie uno**, si segnala, con la colonna che ha fallito.
- **In una corsa con più ancore si taglia nel distacco più ampio** fra due ancore, non con uno stacco fisso. Nel JBL fra EAN e nome successivo ci sono 14,5 pt contro 10,5 dentro l'articolo; con un fattore fisso 66 articoli su 673 si fondevano a coppie.
- **Un testo va alla colonna la cui etichetta gli si sovrappone di più** (`assegna_colonna`), e solo in mancanza alla colonna che comincia più vicino a sinistra. È ciò che legge le colonne allineate a destra: «1,249.50» comincia prima dell'etichetta «Price». Per lo stesso motivo il profilo salva `x_fine_relativo`, la fine del testo della colonna, che serve sulle pagine dove la colonna si ricostruisce dal profilo. **Non va oltre l'inizio della colonna successiva**: sulla pagina 13 dell'Etabeta un testo a tutta larghezza portava la fine della descrizione sopra i prezzi, e con la proposta da quella pagina la copertura scendeva al 95,9% (da pagina 61 al 92,2%; ora 97,4% e 97,0%).
- **Un'etichetta d'intestazione su due righe** («Prezzo al / Pubblico») si riconosce come seguito solo se è vicina, allineata **e dello stesso corpo**. Senza il controllo sul corpo, un titolo di sezione allineato alla prima colonna veniva assorbito nell'intestazione.
- **Testate e piedi non vanno elencati**: sono le righe ripetute alla stessa altezza su almeno metà delle pagine, nelle fasce alta e bassa (`firme_ripetute`, cifre normalizzate).
- **Una pagina può avere più intestazioni**, una per tabella (`rileva_intestazioni`). Si tolgono tutte dal corpo e fanno da taglio; quello che sta sopra la prima **non** si scarta, perché una tabella può proseguire dalla pagina precedente. Le etichette che non sono il nome di un campo, cioè marca e titolo della tabella, diventano la categoria e si abbinano alle colonne del profilo **per posizione** (`_per_posizione`). Per questo il wizard non le salva come intestazioni. «Listino» è un sinonimo di Prezzo: un titolo da solo non fa un'intestazione, servono due etichette riconosciute.
- **Colonne che l'intestazione non nomina** (`analisi_layout.colonne_interne`): nel listino Compumania, esportato da Excel, l'intestazione di ogni sezione è «Codice | Stato | <titolo della sezione> | € ivato | € netto», e sotto il titolo ci sono tre colonne (tipo, marca, descrizione); la descrizione usciva «Computer Compumania Core i3…». Dentro una colonna d'intestazione, una x a cui comincia un testo in almeno il 60% delle righe, almeno due corpi dopo l'inizio e attraversata da non oltre il 5% delle righe è una colonna senza etichetta («Colonna N», proposta dal contenuto e salvata con la sua posizione). Un'etichetta che cambia fra le pagine del campione è un titolo: `da_intestazione` è falso e non si salva come intestazione, o sulla sua tabella la categoria restava vuota. In estrazione **un'etichetta non va oltre l'inizio della colonna dopo** (`risolvi_colonne`): un titolo lungo in testa alla pagina («Schede Video ADD-ON, sk TV, montaggio digitale») si prendeva per sovrapposizione la marca, quando era più lunga di quelle della pagina analizzata (provato nel sintetico `crea_listino_sezioni`; sul Compumania vero non capita). JBL, Etabeta e Midiware restano identici campo per campo.
- **L'inizio di una colonna si ricalcola su ogni pagina dal testo** sotto la sua etichetta (`allinea_al_contenuto`), perché un titolo centrato comincia dopo il suo testo e perché nello stesso catalogo le sezioni hanno colonne in posizioni diverse. Per la stessa ragione la pre-analisi misura l'allineamento pagina per pagina.
- **Tre modi di dividere le altre colonne fra gli articoli**, scelti dai dati e non dal profilo:
  1. **Griglia fitta** (almeno una linea divisoria ogni due righe dell'ancora): ogni cella è un articolo (`celle`). Il bordo sfiora la cima del testo da sotto, quindi taglia una tolleranza più in alto. Le altre colonne prendono anche le celle che seguono **senza codice né prezzo** (`fasce_con_seguito`): nelle schede prodotto una linea separa la prima riga dalle caratteristiche, e 2.900 righe di descrizione andavano perse. Il seguito si ferma alla cella del prossimo articolo, a un titolo, a un'intestazione, a una cella di testo promozionale, **a una cella con un prezzo** (senza questo fermo voci distinte come i cavi al metro si fondevano e la copertura scendeva sotto il 97%) e all'ultima linea della pagina. Un testo grande nella cella di un codice è un **bollino** («NEW» in corpo 12), non un titolo (`_e_bollino`): cambiava la categoria degli articoli seguenti. Basta che la cella abbia dati qualsiasi per scambiare per bollini anche titoli di sezione veri: provato e scartato. Fuori dalla griglia vale `raggruppamento.a_fianco_dei_dati`: una parola sola, larga al massimo 4 corpi e in corpo non oltre 1,5 volte il testo, sovrapposta in altezza a righe di dati nel corpo del testo e dentro un articolo (entro un passo da un'ancora, o sotto un'ancora senza intestazione in mezzo). Ogni condizione esclude un caso misurato: «Vari» (seconda riga di un titolo, accanto a testo promozionale in corpo 11), i loghi di serie «ALA», «VS» (prima della prima tabella) e «HS», «DR» (corpo 16). Sull'Etabeta toglie 45 «NEW»: nessun articolo ha più «NEW» come categoria (erano 52) e 40 descrizioni riprendono le righe che il bollino tagliava. Il caso opposto è **un'ancora scritta più grande** (`raggruppamento.sulla_riga_dei_dati`, `ParserListino._ancore_ingrandite`): un «titolo» nella colonna d'ancoraggio, con l'aspetto di un'ancora, in corpo non oltre 1,5 volte il testo, sulla riga di un prezzo e dei dati di almeno due altre colonne e senza altro testo della sua colonna torna fra le ancore (Midiware: «SOFBCA» in corpo 8 su 6 fondeva due articoli e diventava una categoria). Senza il prezzo e il limite sul corpo passava per codice «STUDIO», scritta grande accanto a testo promozionale (Etabeta, pagina 245).
  2. **Codice centrato** nella cella a interlinea uniforme (`e_centrata` → `fasce_centrate`): cella simmetrica attorno al codice.
  3. **Negli altri casi**: distacco più ampio dopo il punto medio fra due ancore, ma solo se il blocco sotto il taglio arriva all'ancora successiva (`fasce`).
- **Testo in fondo alla pagina** (`raggruppamento.coda_staccata`, sulla descrizione dell'ultimo articolo della pagina): dopo uno stacco di almeno 2 interlinee con sole righe di descrizione (nessun codice né prezzo: nei kit il secondo codice sta nello stacco), il blocco si toglie se lo stacco supera 4 interlinee, se è in un altro corpo (oltre il 5%: «VEDI vari SUB…» è in corpo 10 su 9) o se nessuna sua riga è allineata a sinistra con una riga dell'articolo, codice compreso (testo centrato). Il testo tolto va negli avvisi, non si perde in silenzio. Vale anche nella griglia: lì la nota sta in un riquadro suo e `fasce_con_seguito` la prendeva come seguito. L'allineamento si confronta col codice perché le caratteristiche delle schede cominciano a tutta larghezza dall'inizio della sua colonna (pagine 25, 64, 243). Sull'Etabeta: 25 candidati, 14 staccati («Sul sito www.cloud.co.uk…», lo schema di p100, «LINEA IN ESAURIMENTO» di p321).
- **Ancora Modello**: se nel documento almeno il 70% dei valori ha l'aspetto di un codice (`aspetto_codice`), le righe che non lo hanno non sono articoli. In griglia, una cella senza prezzo e senza codice non è un articolo.
- **Testo dal PDF**: `text_extractor` unisce gli span che si toccano (`_unisci_contigui`) e ricompone legature e glifi di Calibri scritti male da Acrobat Distiller («Ɵ»→ti, «Ʃ»→tt, «ƫ»→tti, «Ampliﬁ catore»). Senza, le descrizioni del catalogo Etabeta uscivano spezzate. Due eccezioni all'unione, entrambe a uno spazio di confine: **un bollino** (una parola in maiuscolo più grande di oltre il 15%, dopo uno spazio: «23550 » in corpo 9 + «NEW» in corpo 12) resta a parte, col testo che lo segue in un altro corpo; uniti, il codice diventava un titolo, l'articolo spariva e il titolo era la categoria dei seguenti (Etabeta: PMU-Ts, 23550, 23600, SK213-T3 ritrovati, 18 categorie corrette). Il contrario, una scritta grande seguita da una piccola («SW Turbo Speaker Horn», «NEW MI SERIE»), resta unito: divisa, la parte piccola cadeva fra i dati e diventava un articolo. **Due numeri** separati da uno span di solo spazio sono due celle (Midiware 2017: «15.750,00 13.853,00» finiva nella colonna dopo).
- **Trattino a fine riga** (`article_parser.Vocabolario`, solo per descrizione e colonne di testo, mai per codici e modelli): il trattino si toglie se la parola intera compare nel documento («processo-re», «Alo-ne»); se il pezzo di sinistra non è una parola («recen-temente»), solo se **il documento sillaba**, cioè se `prepara` trova più trattini a capo confermati come parole spezzate che come composti. Restano composti («U-bracket», «Plug-in»), sigle («MTC-29UB»), maiuscole dopo il trattino («Bi-Amp») e coppie di parole («two-part»). Senza la condizione sul documento, il JBL sintetico perdeva il trattino di «water-resistant». Misurato: JBL nessun cambiamento (0 sillabazioni confermate contro 46 composti), Etabeta 39 parole ricomposte.
- **Il validatore segnala solo i campi che il profilo prevede**: su un listino senza colonna Modello, «Modello mancante» su ogni riga era rumore.
- **Le anomalie non si correggono mai in automatico.** Gli errori dell'estrazione stanno in `Articolo.note_estrazione` (per campo) e un intervento dell'utente sul campo li cancella (`Articolo.imposta`). Quelle del validatore stanno in `Articolo.anomalie` e si ricalcolano da zero dopo ogni modifica, perché i duplicati dipendono da tutte le righe. Non si scartano nemmeno i duplicati. Il filtro dell'anteprima raggruppa i messaggi per tipo (`data_validator.tipo_anomalia`: il testo prima di «:», «(», ««», «—», senza «a pagina N» né «nella colonna») e li conta per articolo (`conta_tipi`); un messaggio nuovo deve dire il suo tipo prima dei dettagli.
- **Tutto ciò che apre il PDF gira in un processo separato** (`processors/lavori.esegui`: estrazione, analisi del wizard, anteprima; lato interfaccia `gui/lavoro.LavoroInProcesso`, contesto `spawn`), non in un thread. PyMuPDF tiene il GIL durante l'analisi di ogni pagina: in un thread l'interfaccia restava ferma per tutto il lavoro (5 s su un PDF di 1.210 pagine). Ne seguono due obblighi: ogni script che apre una finestra deve avere la guardia `if __name__ == "__main__"`, e `main.py` chiama `multiprocessing.freeze_support()` per l'eseguibile. Si ridisegna solo l'ultimo avanzamento ricevuto, perché aggiornare a ogni pagina bloccava la finestra. L'avanzamento copre anche la prima passata (`estrai_listino(..., lettura=)`, messaggio `("lettura", n, tot)`), che è il 70-76% del tempo: la barra ci dedica `PESO_LETTURA`. Gli avvisi dell'estrazione si leggono tutti in `dialoghi.FinestraAvvisi`, non modale (prima un messaggio con i primi 20). Tabella e dettaglio, e nel wizard pagina, mappatura e anteprima, sono in pannelli con separatori trascinabili (`gui/pannelli.py`, PanedWindow di Tk col colore del contenitore). La larghezza delle colonne si misura sulle 5 scritte più lunghe di un campione: misurarle tutte bloccava la finestra 360 ms alla fine dell'estrazione (la prima misura di ogni carattere costa).
- **`get_text("dict")` va chiamato con `FLAG_TESTO`**, che esclude le immagini: di default porta con sé i byte di ogni immagine ed era il 75% del tempo di estrazione.
- **Percorsi** (`percorsi.py`): le risorse sono in sola lettura (`_MEIPASS` nell'eseguibile, che può stare in Program Files). Log e regole personali vanno in `%LOCALAPPDATA%\PDFListinoExtractor`, che aggiornamenti e disinstallazione non toccano. `config.carica_regole` unisce alle regole distribuite quelle di `%LOCALAPPDATA%\PDFListinoExtractor\supplier_rules.json`, letto in `utf-8-sig` perché il Blocco note salva col BOM; se il file è illeggibile o non rispetta lo schema viene ignorato con un avviso e non blocca l'avvio. Un file nella versione 1 (formato della 1.0.0) si legge ancora. Il wizard e i pulsanti «Modifica…»/«Rinomina…»/«Rimuovi» accanto al menu Fornitore scrivono **solo** quel file (`config.salva_`/`rinomina_`/`rimuovi_fornitore_personale`, tutte via `_scrivi_personali`): schema verificato prima di toccare file e copia, file temporaneo + `os.replace`, copia `.bak`, `utf-8-sig`. Si rinominano e si rimuovono solo i fornitori personali (`config.chiavi_personali`); quelli distribuiti restano in sola lettura, e togliere un personale con la stessa chiave rimette in uso quello distribuito. Il nome deve restare unico, maiuscole a parte, perché menu e wizard riconoscono il fornitore dal nome. «Esporta fornitori…»/«Importa fornitori…» (sotto il wizard) servono a cambiare postazione: `config.esporta_fornitori_personali` scrive solo fornitori e sinonimi del file personale, senza il predefinito e senza `.bak`; `config.importa_fornitori` valida il file (anche versione 1) prima di toccare quello personale e **non sovrascrive mai**: chiave già personale → `<chiave>_importato`, nome già nel menu → « - Importato» (poi « 2», « 3»), fornitore identico a uno locale (anche col nome dato da un'importazione precedente) → saltato, così reimportare non crea doppioni. Una chiave che è solo di un fornitore distribuito lo sostituisce, come sulla postazione di partenza.
- **Pagina da cui partire nel wizard** (`analisi_layout.pagina_consigliata`, su `AnalisiLayout.pagine_campione`): per ogni pagina del campione l'analisi conta le scritte con l'aspetto di un prezzo e guarda se c'è un'intestazione. Se la pagina analizzata ha meno di un quarto della mediana dei prezzi del campione (indice, copertina, divisori), consiglia la prima pagina con almeno la mediana e un'intestazione. Sull'Etabeta da pagina 1 consiglia la 13 (copertura 97,4% con la proposta da lì); sul JBL la pagina 1 (3 prezzi, mediana 5) non è debole e nessuna pagina viene consigliata. Nel wizard il menu «Pagine del campione» segna con ✔/○ le pagine di `pagine_con_tabella`, «Prossima tabella» usa `wizard.prossima_tabella`, e alla prima analisi di un PDF aperto (non quando l'utente sceglie una pagina) si salta da soli alla pagina consigliata; altrimenti la si suggerisce nella barra di stato. `tools/prova_wizard.py` sceglie la pagina, quindi non salta.
- **Finestre in primo piano** (`dialoghi.in_primo_piano`): su Windows un CTkToplevel appena creato finisce dietro la finestra principale (verificato con `GetForegroundWindow`), e «Configura nuovo fornitore» sembrava non fare nulla. Il wizard e gli avvisi si portano davanti col fuoco, «sempre in primo piano» per un attimo e poi di nuovo normali.
- **Pannello delle colonne del wizard**: una riga compatta per colonna (colore, etichetta, esempi; ruolo e nome nell'Excel a destra, menu larghi `LARGHEZZA_RUOLO`), ancora, formato e parentesi in «Altre opzioni» richiuse col riassunto dei valori, che si aprono da sole se un errore li riguarda. Prima sul Midiware si vedevano due colonne e mezza su sette. I numeri delle colonne sulla pagina stanno sopra l'intestazione, non sopra le etichette.
- **Anteprima del wizard disegnata sulla pagina**: solo per un'estrazione di pagine scelte `ParserListino.geometrie` registra, per pagina, intestazioni, titoli rimasti e bollini scartati (`GeometriaPagina` in `models.py`), che arrivano in `RisultatoEstrazione.geometria`; l'estrazione intera non registra nulla. Il wizard disegna tutte le intestazioni (`AnalisiLayout.intestazioni`), un riquadro numerato per articolo (`Articolo.bbox`) a colori alterni, i titoli in rosso e i bollini in grigio; riga della tabella e articolo sulla pagina si richiamano a vicenda. Cambiare la mappatura toglie i riquadri, che venivano da quella di prima.
- **Modificare un fornitore nel wizard** (`ModelloWizard.applica_profilo`): le colonne salvate si riabbinano a quelle trovate sulla pagina prima per etichetta, poi per posizione relativa (`abbina_colonne`, fasce contigue fra una colonna e la successiva: un `x_relativo` arrotondato per difetto cadeva fuori). La chiave resta la stessa anche cambiando nome. Al salvataggio `_con_originale` sovrappone la mappatura al profilo com'era: restano `escludi`, `prezzo_massimo`, le regex di EAN e prezzo, le spaziature, una regex del codice personalizzata e le intestazioni aggiunte a mano. Sul JBL, aprire il profilo e salvarlo senza toccare nulla dà gli stessi 673 articoli (`tests/test_universale.py`).
- **Versione**: l'unica fonte è `version.py`, letto dal titolo della finestra, dal `.spec` (proprietà dell'eseguibile) e da `build_installer.bat`. L'`AppId` in `installer/PDFListinoExtractor.iss` non va mai cambiato, o un aggiornamento verrebbe installato come un programma diverso. `[InstallDelete]` svuota `_internal` a ogni aggiornamento. `EDITORE` resta vuoto finché non se ne indica uno reale.
- **Colonne dinamiche: nome e ruolo sono separati.** `ColonnaUscita(chiave, etichetta, ruolo)` (`processors/models.py`) è una colonna della tabella e del foglio `Listino`. `profilo.colonne_uscita` le ricava dal profilo, nell'ordine delle sue colonne: una colonna `identificativo` ne dà una per campo impilato (il JBL ha 3 colonne fisiche e 5 in uscita), `ignora` nessuna. Arrivano in `RisultatoEstrazione.colonne` e da lì a tabella, export, report e riquadro di dettaglio. Il motore continua a ragionare per ruolo: i cinque campi restano attributi di `Articolo` (ancora, regex, seguito non cambiano); il ruolo `testo_generico` (colonna in più) va in `Articolo.altri["testo_N"]`, e `Articolo.valore`/`imposta` valgono per qualsiasi chiave. Il nome è l'`etichetta` del profilo; **senza `etichetta` vale il nome standard**, quindi un profilo salvato prima esporta come prima. Il wizard propone come nome l'intestazione del PDF solo se è il nome di quel campo (sull'Etabeta sopra la descrizione c'è il titolo della tabella), anche su due righe (`etichetta_completa`: «Prezzo al Pubblico»), e la salva solo se diversa da quella standard. Una colonna di testo si salva con la sua intestazione, per ritrovarla nelle altre pagine, e la sua etichetta non entra nella categoria. Proposta automatica di `testo_generico`: etichetta che non è il nome di un campo, sopra testo allineato, quando quel ruolo c'è già da un'intestazione o, per «modello», l'articolo ha già il codice.
- **Più prezzi nella stessa cella della colonna Prezzo**: una riga per prezzo (`ParserListino._righe_per_prezzo`, `raggruppamento.dividi_per_prezzo`, tagli a metà fra un prezzo e il successivo perché il testo di ogni voce è centrato sulla sua riga; una colonna con righe in una fascia sola è comune a tutte). Se ogni prezzo ha la sua ancora sono articoli distinti finiti in una cella (Etabeta: RSL-8/RSL-16, WP1-SI/SP, CB10/30/70, BAL-08/1m e /2m); se l'ancora è una e un'altra colonna ha un testo suo per ogni prezzo sono varianti (ACT-6Dante: due descrizioni, due prezzi), con la nota «Variante». Altrimenti, come «Articolo con due prezzi» del listino sintetico (una descrizione sola), non si sceglie: resta «Più prezzi», e nell'anteprima l'editor della cella diventa un menu coi prezzi trovati. Così anche più prezzi sulla stessa riga («€ 53,00 € 60,00», `_prezzi_nella_riga`), che prima erano «Prezzo non riconosciuto». Sull'Etabeta la copertura sale al 97,8%. **Un prezzo non è mai un'etichetta d'intestazione** (`_indice_colonna`): «EUR 20,00» cominciava col sinonimo «eur» e una riga di dati con «articolo» nella descrizione diventava un'intestazione.
- **Più prezzi per riga** (ruolo `altro_prezzo`, in `Articolo.altri["prezzo_N"]`, listino Midiware: Listino | Dealer | Premium | Street): il prezzo dell'articolo resta uno, e decide ancora, «Prezzo mancante» e la copertura; gli altri sono un `Decimal` (o il testo del PDF con una nota, se non è un prezzo o ce ne sono due), esportati come numeri e mostrati, ordinati e corretti come il prezzo (`preview_table.testo_cella`, `RUOLI_PREZZO`). Il wizard propone come Prezzo la colonna che l'etichetta chiama così, o la prima, e le altre come «Altro prezzo» col loro nome, salvato anche come intestazione: senza, quattro «Prezzo» non si potevano salvare, ogni riga aveva «Secondo prezzo» e sulle pagine che proseguono una tabella la categoria era «Dealer · Premium · Street». Un «+» o un «-» staccato dopo il prezzo (variazione dal listino precedente, Midiware 2017: «249,00 -») si toglie prima di leggerlo (`_SEGNO_VARIAZIONE`).
- **Colonna Marca** (ruolo `marca`, in `Articolo.altri["marca"]`): il valore è l'etichetta che l'intestazione di ogni tabella scrive sopra quella colonna (Etabeta: «VISSONIC | Articolo | titolo | Listino»), abbinata per posizione (`_per_posizione`); il testo sotto la colonna è escluso come per `ignora`. Il wizard la propone per una colonna che sarebbe «ignora» con un'etichetta d'intestazione che cambia fra le pagine del campione. Una tabella che prosegue in cima alla pagina successiva tiene la marca. **Su una pagina senza intestazione la marca della tabella precedente vale solo se il testo della pagina la nomina** (`_nominata`): ereditata alla cieca era sbagliata in 208 articoli (Chromateq a pagina 224, AVMATRIX a 325, Nearity a 23, dove l'intestazione senza «Articolo» non viene riconosciuta). Una marca vuota è un'anomalia «Marca mancante» se il profilo prevede la colonna.
- **Formato dell'export**: dipende dal ruolo. Modello, codice, EAN e colonne di testo sono celle di testo (`@`); il prezzo è un numero (`#,##0.00`) e, se manca, una cella vuota, non `0`; la descrizione va a capo. Il codice resta tra parentesi (`codice_con_parentesi`). La descrizione ripete il nome del modello dove è vuota (accessori) **solo se il profilo ha una colonna Descrizione**. Non c'è una colonna Marca: nell'Etabeta la marca si trova solo nella categoria, nella forma «MARCA · titolo della tabella».
- **Limiti noti sull'Etabeta**, misurati e non risolti:
  - con la colonna Marca, 219 articoli (oltre alle 17 righe dell'indice) restano con «Marca mancante»: su quelle pagine la marca è solo nel logo, un'immagine, o in un'intestazione non riconosciuta;
  - 228 righe di descrizione ancora perse;
  - qualche parola andata a capo resta col trattino quando il pezzo di sinistra è anche una parola e quella intera non compare altrove («com-pattata»: «com» viene da «.com»).
- **Limite noto sul Midiware**: la categoria è l'ultimo titolo, cioè la sezione («Accessori»); la marca, un titolo più grande sopra le sezioni («1010MUSIC», «CME»), non entra né nella categoria né nella colonna Marca, che legge solo le intestazioni delle tabelle.

## Test

`tests/sintetico.py` (impaginazione JBL), `tests/sintetico_generico.py` (layout opposto; `crea_listino_colonne` con le varianti a colonne dinamiche «tre» e «colore», attese in `ATTESI_COLONNE` come righe dell'Excel) e `tests/sintetico_catalogo.py` (catalogo Etabeta, con e senza griglia) generano PDF con i risultati attesi in `ATTESI`. Per un caso nuovo si aggiungono lì sia il contenuto della pagina sia il risultato atteso. Il font `helv` dei PDF sintetici non ha il «€»: scrivere «EUR». Per i test con Tk non serve un display virtuale su Windows. Le azioni da tastiera della tabella (`sposta_colonna`, `modifica_attiva`, `conferma_editor`, `vai_da_verificare`) sono metodi: i test le chiamano direttamente, perché con la finestra nascosta Tk non consegna i tasti; i tasti veri si provano sulla finestra visibile con `event_generate`. Una suite verde però non basta: il blocco dell'interfaccia, il problema del BOM, l'intestazione che assorbiva i titoli, il «Modello mancante» su ogni riga e tutti i difetti del catalogo Etabeta sono emersi solo provando l'applicazione vera o un PDF vero (`tools/prova_gui.py`, `tools/prova_wizard.py`, `--collaudo`, `--collaudo-wizard`, `tools/collaudo_installer.ps1`).
